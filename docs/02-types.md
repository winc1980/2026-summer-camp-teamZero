# 2. 型と数値

> **この章で分かること**
>
> - DS での型のサイズ
> - `u8` / `u16` / `u32` の使い方
> - 数値まわりでよく踏む罠

---

## 2.1 型のサイズは環境で変わる

C の規格は `int` が何ビットかを決めていません。DS（ARM 32bit）ではこうなります。

| 型 | DS でのサイズ | 備考 |
| --- | --- | --- |
| `char` | 1 | **ARM では符号なし（0〜255）** |
| `short` | 2 | |
| `int` | **4** | -21 億 〜 21 億 |
| `long` | **4** | PC（64bit Linux）では 8 |
| `long long` | 8 | |
| `float` / `double` | 4 / 8 | **DS では避ける（2.6）** |
| ポインタ | **4** | PC（64bit）では 8 |

**PC と DS で `long` とポインタのサイズが違います。**
「PC で動いたのに DS で壊れた」の原因になりがちです。

---

## 2.2 だから固定幅の型を使う

`<stdint.h>` にはビット幅が名前に入った型があります。libnds はこれに短い別名を付けています。

| libnds | 実体 | 意味 |
| --- | --- | --- |
| `u8` | `uint8_t` | 符号なし 8bit（0〜255） |
| `u16` | `uint16_t` | 符号なし 16bit（0〜65535） |
| `u32` | `uint32_t` | 符号なし 32bit |
| `s8` `s16` `s32` | `int8_t` … | 符号あり |
| `vu16` `vu32` | `volatile ...` | ハードウェアレジスタ用（8 章） |

DS 界隈のコードはほぼこの表記です。**読めるようにしておいてください。**

### 使い分け

```c
u16 color = RGB15(31, 0, 0);       // ハードの仕様で幅が決まっているもの
u32 keys  = keysHeld();

for (int i = 0; i < 10; i++) { }   // 普通のループカウンタは int でよい
int hp = 3;                        // 負になりうるものは int
```

**「小さい型の方が速い」わけではありません。** ARM は 32bit 単位が一番速いです。
`u8` / `u16` が効くのは、**配列にしたとき**（1000 要素なら 1KB vs 4KB）だけだと思ってください。

---

## 2.3 罠 1: 小さい型に入れると切り詰められる

C では、`int` より小さい型は**計算の前に自動で `int` になります**（整数昇格）。

```c
u8 a = 200;
u8 b = 100;

int sum1 = a + b;     // 300。計算は int で行われるので正しい
u8  sum2 = a + b;     // 44 !! u8 に代入する瞬間に切り詰められる
```

同じことが掛け算でも起きます。

```c
u16 w = 300, h = 300;
u16 area = w * h;     // 90000 が u16 に入らず 24464 になる
int area = w * h;     // 90000。これは OK
```

**代入先の型が結果を収められるか、を意識してください。**

---

## 2.4 罠 2: 符号なしの引き算

符号なしの型は負の数を表せません。0 より小さくなると、**巨大な正の数**になります。

```c
u32 count = 0;
for (u32 i = 0; i < count - 1; i++) {    // count-1 は 4294967295
    ...                                   // 43 億回まわろうとする
}
```

符号あり と 符号なし を比較すると、符号ありの方が変換されます。

```c
int i = -1;
u32 u = 1;
if (i < u) { }        // 偽！ -1 が 4294967295 に化ける
```

> **指針: 引き算をする変数、負になりうる変数は、素直に `int` を使う。**
> `u32` を使うのは、ビットの並びとして扱うもの（キー入力、フラグ、色）だけにしてください。

---

## 2.5 罠 3: 整数の割り算

C の `/` は整数同士だと**小数を切り捨てます**。

```c
7 / 2      // 3
-7 / 2     // -3（0 方向に切り捨て）
```

よくあるミス:

```c
int percent = hp / maxHp * 100;    // ❌ hp < maxHp なら 0/1 → 常に 0%
int percent = hp * 100 / maxHp;    // ✅ 掛けてから割る
```

**割り算は最後に。** これだけ覚えておいてください。

なお DS の ARM9 には**割り算の命令がありません**。`/` は関数呼び出しになるので、
毎フレーム大量に割るのは避けます（2 のべき乗ならシフト → 8 章）。

---

## 2.6 罠 4: DS で `float` は遅い

BlocksDS のビルドフラグを見てください。

```makefile
ARCH := -mthumb -mcpu=arm946e-s+nofp
#                            ^^^^^ no floating point
```

**DS の CPU に浮動小数点の計算回路がありません。**
`float a * b` は CPU 命令 1 個ではなく、**ソフトウェアの関数呼び出し**になります。
整数の数十倍のコストです。

- 起動時の計算や、1 フレームに数回程度なら `float` でも構いません
- **毎フレーム全キャラの座標計算に使うと、確実に処理落ちします**

代わりに使うのが **固定小数点**で、[9 章](09-fixed-point.md)のテーマです。
ひとまず「DS では `float` を使わない」とだけ覚えておいてください。

---

## 2.7 罠 5: ARM では `char` が符号なし（発展）

素の `char` が `signed` か `unsigned` かは環境によります。

| 環境 | 素の `char` |
| --- | --- |
| 手元の PC（x86） | signed（-128〜127） |
| **DS（ARM）** | **unsigned（0〜255）** |

```c
char c = 200;
if (c < 0) {
    // PC: ここに来る（-56 になる）
    // DS: 来ない（200 のまま）
}
```

対策は簡単で、**数値として使うなら `u8` / `s8` を明示する**だけです。
DS のコードでは自然と `u8` を使うので、あまり困りません。
「PC のサンプルを持ってきたら挙動が変わった」ときだけ思い出してください。

## 2.8 その他の細かい話

```c
bool alive = true;         // <stdbool.h>。libnds では nds.h に入っている
if (ptr)   { }             // ptr != NULL と同じ（0 が偽、それ以外が真）

0x2A                       // 16 進。レジスタの値はほぼこの表記
052                        // 先頭 0 は 8 進！ 事故のもと

sizeof(int)                // 型は size_t。printf の書式は %zu

#define MAX_ENEMIES 32     // 定数はこれか enum で。const int は配列サイズに使えない
enum { MAX_ENEMIES = 32 };
```

## 確認問題

**Q1.** DS 上でこれは何を出力しますか。

```c
u8 a = 250, b = 10;
printf("%d\n", a + b);
```

<details><summary>解答</summary>

**260**。

`a + b` は自動的に `int` で計算されるので 260 になります。
これを `u8` の変数に代入していれば 4 に切り詰められましたが、
ここでは `printf` に直接渡しているので 260 のままです。
</details>

**Q2.** HP の割合をパーセントで出したい。次のコードは何が問題ですか。

```c
int hp = 37, maxHp = 100;
int percent = hp / maxHp * 100;
```

<details><summary>解答</summary>

整数の割り算なので `37 / 100` が `0` になり、`0 * 100 = 0`。常に 0% です。

```c
int percent = hp * 100 / maxHp;    // 3700 / 100 = 37
```

**掛けてから割る。**
</details>

**Q3.** DS で `float` を避けるべき理由は何ですか。

<details><summary>解答</summary>

DS の CPU（ARM946E-S）に浮動小数点演算回路（FPU）が無いためです。
ビルドフラグの `-mcpu=arm946e-s+nofp` がその証拠です。

`float` の計算はすべてソフトウェアの関数呼び出しになり、整数演算の数十倍かかります。
67MHz の CPU で 60fps を保つには重すぎます。

ただし、起動時の初期化やステージ読み込み時など、
**1 フレームあたりの実行回数が少ない**処理なら使っても問題ありません。
</details>
