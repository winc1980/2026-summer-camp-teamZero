# 4. ポインタ

> **この章で分かること**
>
> - `&` と `*` を図でイメージできる
> - out 引数を書ける・読める
> - 読むだけの引数に `const` を付けられる
> - DS のハードウェアレジスタが「決まったアドレスのポインタ」だと理解する

**この章が C 最大の山場です。** 他の言語から来た人がつまずくのはほぼ全部ここに集約されます。
逆に言えば、ここを越えれば残りは応用です。

---

## 4.1 メモリはでかいバイト配列

プログラムが使えるメモリは、**0 番地から順に番号が振られた、1 バイトの箱の列**です。

```
アドレス:  0x02000000  0x02000001  0x02000002  0x02000003  0x02000004 ...
         ┌──────────┬──────────┬──────────┬──────────┬──────────┐
         │    2A    │    00    │    00    │    00    │    ...   │
         └──────────┴──────────┴──────────┴──────────┴──────────┘
         └──────────── int x = 42 (4バイト) ────────────┘
```

`int x = 42;` と書くと、コンパイラはメモリのどこか 4 バイトを `x` という名前に割り当て、
そこに 42 を書き込みます。

**ポインタとは、この「アドレス（番地）」を値として持つ変数です。** それだけです。

DS では**アドレスは 32bit（4 バイト）**なので、どんなポインタも `sizeof` すると 4 になります。

## 4.2 `&` と `*`

```c
int  x = 42;
int *p = &x;      // p は x のアドレスを持つ

printf("%d\n", x);     // 42        値そのもの
printf("%p\n", &x);    // 0x2000010 x のアドレス
printf("%p\n", p);     // 0x2000010 p が持っているアドレス（= x のアドレス）
printf("%d\n", *p);    // 42        p が指す先の値

*p = 100;              // p が指す先に 100 を書き込む
printf("%d\n", x);     // 100       x が変わった！
```

図にするとこうです。

```
         x                        p
    ┌─────────┐              ┌──────────────┐
    │   42    │  ◀───────────│  0x02000010  │
    └─────────┘              └──────────────┘
    0x02000010               0x02000020

    *p ＝「p が指している箱の中身」＝ x
    &x ＝「x の箱の住所」        ＝ 0x02000010
```

覚え方:

- **`&` は「〜のアドレス」** — アドレスを**取り出す**
- **`*` は「〜が指す先」** — アドレスを**たどる**（間接参照／デリファレンス）

`&` と `*` は互いに逆の操作です。`*&x` は `x` と同じ意味になります。

## 4.3 宣言の読み方

ここが初学者を混乱させる最大の原因です。**`*` は 2 つの違う場面で登場します。**

```c
int *p;        // 【宣言】p は「int へのポインタ」型の変数である
*p = 5;        // 【式】  p が指す先に 5 を代入する
```

宣言の `*` は「型の一部」、式の `*` は「間接参照演算子」です。まったく別物です。

宣言は **「`*p` の型が `int` である」** と読むとしっくりきます。

```c
int  *p;       //  *p が int   → p は int へのポインタ
int **pp;      // **pp が int  → pp は「int へのポインタ」へのポインタ
```

### `int *p` と書く理由

```c
int* a, b;     // a はポインタだが、b は ただの int！
int *a, *b;    // 両方ポインタ
```

`*` は変数名の側に付くので、**`int *p`** と書く習慣にしておくと事故が減ります。

## 4.4 NULL — 「どこも指していない」

```c
int *p = NULL;      // どこも指していない、と明示する

if (p != NULL) {    // 使う前に必ずチェック
    *p = 5;
}
if (p) { }          // 同じ意味。こちらもよく使われる
```

`NULL` はアドレス 0 です。**`NULL` を間接参照するのは未定義動作**で、
DS では大抵の場合クラッシュするか、BIOS 領域を読んでゴミが返ってきます。

もっと危ないのが**未初期化ポインタ**です。

```c
int *p;        // 初期化していない → 中身は前に使われたゴミの値
*p = 5;        // ランダムなアドレスに書き込む。何が壊れるか分からない
```

**ポインタは宣言時に必ず初期化してください。** 指すものが決まっていなければ `NULL` を入れます。

## 4.5 用途 1: 呼び出し元の変数を書き換える（out 引数）

3 章で見た通り、C の引数は値渡しです。呼び出し元を書き換えたければアドレスを渡します。

```c
void damage(int *hp, int amount)
{
    *hp -= amount;
    if (*hp < 0) *hp = 0;
}

int playerHp = 10;
damage(&playerHp, 3);
printf("%d\n", playerHp);    // 7
```

**libnds のこのパターンを読めるようになるのが当面のゴールです。**

```c
touchPosition touch;         // 中身は空
touchRead(&touch);           // touch のアドレスを渡す → 関数が中身を埋める
printf("%d,%d\n", touch.px, touch.py);
```

```c
int textureID;
glGenTextures(1, &textureID);   // textureID に ID が書き込まれる
```

「関数が結果を書き込む場所を、呼び出し側が用意して、その住所を教える」というモデルです。

### 値の交換

古典的な例。

```c
void swap(int *a, int *b)
{
    int t = *a;
    *a = *b;
    *b = t;
}

int x = 1, y = 2;
swap(&x, &y);      // x=2, y=1
```

## 4.6 用途 2: 大きなデータをコピーせずに渡す

構造体は値渡しすると丸ごとコピーされます。

```c
typedef struct {
    int  x, y, vx, vy, hp;
    u16  sprite[64 * 64];      // 8KB！
} Enemy;

void updateSlow(Enemy e);      // 呼ぶたびに 8KB コピー。論外
void updateFast(Enemy *e);     // 4 バイト（アドレス）だけ渡す
```

**DS では構造体はポインタで渡すのが基本**と覚えてください。

```c
void enemyUpdate(Enemy *e)
{
    e->x += e->vx;     // (*e).x と同じ意味。矢印記法は 6 章
    e->y += e->vy;
}
```

## 4.7 `const` — 「書き換えない」という約束

`const` は**ポインタ引数を受け取る関数の意図を表明する**ために使います。

```c
// この関数は e の中身を読むだけで、書き換えない
int enemyGetHp(const Enemy *e)
{
    return e->hp;
    // e->hp = 0;   ← 書こうとするとコンパイルエラーになる
}
```

読み手にとって「この関数は引数を壊さない」と一目で分かるうえ、
コンパイラが実際に守らせてくれます。**読むだけの引数には積極的に `const` を付けてください。**

### `const` の位置（発展）

`*` の左に書けば「指す先が const」、右に書けば「ポインタ自身が const」です。

```c
const int *p;         // *p = 5 は不可。p = &other は可  ← 実務ではほぼこれ
int *const p = &x;    // *p = 5 は可。p = &other は不可
```

## 4.8 ポインタ演算

ポインタに整数を足すと、**「型のサイズ」単位で進みます**。バイト単位ではありません。

```c
int arr[4] = {10, 20, 30, 40};
int *p = arr;          // arr は先頭要素のアドレスに化ける（5 章）

printf("%d\n", *p);        // 10
printf("%d\n", *(p + 1));  // 20   アドレスは +4 バイト進む
printf("%d\n", *(p + 2));  // 30

p++;                       // アドレスが +4 バイト
printf("%d\n", *p);        // 20
```

```
     p        p+1      p+2      p+3
     ▼        ▼        ▼        ▼
  ┌────────┬────────┬────────┬────────┐
  │   10   │   20   │   30   │   40   │   ← int なので 1 要素 4 バイト
  └────────┴────────┴────────┴────────┘
  +0       +4       +8       +12  (バイト)
```

`u8 *` なら 1 バイトずつ、`u16 *` なら 2 バイトずつ進みます。
「配列の要素を順に見る」という意図がそのまま書けるわけです。

ポインタ同士の**引き算**は「要素いくつ分離れているか」を返します。

```c
int *a = &arr[0];
int *b = &arr[3];
printf("%td\n", b - a);    // 3（12 ではない）
```

## 4.9 DS ではこう使う: ハードウェアレジスタ

DS のハードウェアは、**特定のメモリアドレスへの読み書き**で制御します
（メモリマップド I/O）。libnds はそれをこう定義しています。

```c
#define REG_DISPCNT (*(vu32 *)0x04000000)
```

分解して読んでみましょう。

| 部分 | 意味 |
| --- | --- |
| `0x04000000` | ディスプレイ制御レジスタのアドレス（ただの整数） |
| `(vu32 *)0x04000000` | それを「`volatile u32` へのポインタ」だと解釈する |
| `*(vu32 *)0x04000000` | そのアドレスの中身（32bit）そのもの |

こうしておくと、普通の変数のように書けます。

```c
REG_DISPCNT = MODE_0_2D | DISPLAY_BG0_ACTIVE;   // 0x04000000 に値を書き込む
```

`libnds` の `math.h` を覗くと、まさにこのパターンが並んでいます。

```c
#define REG_DIVCNT      (*(vu16 *)(0x04000280))
#define REG_DIV_NUMER   (*(vs64 *)(0x04000290))
#define REG_DIV_RESULT  (*(vs64 *)(0x040002A0))
```

### `volatile` が必須な理由

`vu32` は `volatile uint32_t` です。`volatile` が無いと、
コンパイラは「同じアドレスを 2 回読んでも値は同じはず」と考えて 2 回目の読み込みを消したり、
「この書き込みは誰も読まないから不要」と判断して消したりします。

ハードウェアレジスタは**プログラムの外側（ハードウェア）から値が変わる**ので、
その最適化は誤りです。`volatile` は「**このアクセスを勝手に省略・並べ替えするな**」という指示です。

詳しくは 8 章で扱います。

## 4.10 よくあるバグ

### (a) ローカル変数のアドレスを返す

```c
int *makeCounter(void)
{
    int count = 0;
    return &count;      // count は関数を抜けると消える。返したアドレスは無効
}
```

これは **dangling pointer（ダングリングポインタ）** と呼ばれます。
呼び出し直後は「たまたま」まだ値が残っていて動くことがあり、
別の関数を呼んだ瞬間にスタックが上書きされて壊れます。
**「動いたり動かなかったりするバグ」の典型です。**

`-Wall` は多くの場合これを検出してくれます。

```
warning: function returns address of local variable
```

### (b) 解放後に使う（use-after-free）

```c
u8 *buf = malloc(100);
free(buf);
buf[0] = 1;         // 解放済みメモリへの書き込み。未定義動作
```

`free` した直後に `buf = NULL;` を代入する習慣を付けると、
少なくとも「NULL 参照でクラッシュ」という**気づけるバグ**に変換できます。

## 確認問題

**Q1.** `&x` と `*p` はそれぞれ何を意味しますか。1 行で説明してください。

<details><summary>解答</summary>

- `&x` : 変数 `x` が置かれているメモリのアドレス（住所）
- `*p` : ポインタ `p` が持っているアドレスの場所にある値（中身）

</details>

**Q2.** 次の 2 つの宣言の違いを説明してください。

```c
const Enemy *a;
Enemy *const b;
```

<details><summary>解答</summary>

- `const Enemy *a` — **指す先が const**。`a->hp = 0;` は不可。`a = otherEnemy;` は可。
  「読み取り専用で渡す」ときの標準形。
- `Enemy *const b` — **ポインタ自身が const**。`b->hp = 0;` は可。`b = otherEnemy;` は不可。
  実務ではほとんど使いません。

判別法: `*` より左の `const` は指す先、右の `const` はポインタ自身。
</details>

**Q3.** 次の関数のバグを指摘してください。

```c
char *makeMessage(int score)
{
    char buf[64];
    snprintf(buf, sizeof(buf), "SCORE: %d", score);
    return buf;
}
```

<details><summary>解答</summary>

`buf` はローカル変数（スタック上）なので、関数を抜けた時点で無効になります。
返したポインタはダングリングポインタで、参照すると未定義動作です。
呼び出し直後は「たまたま」正しく見えることがあるのが最悪の点です。

修正案 3 つ:

```c
// (a) 呼び出し側にバッファを用意させる（C で最も一般的）
void makeMessage(char *out, size_t outSize, int score)
{
    snprintf(out, outSize, "SCORE: %d", score);
}

// (b) static にする（再入不可・上書きされるので注意して使う）
const char *makeMessage(int score)
{
    static char buf[64];
    snprintf(buf, sizeof(buf), "SCORE: %d", score);
    return buf;
}

// (c) malloc する（呼び出し側に free の責任が生じる）
char *makeMessage(int score)
{
    char *buf = malloc(64);
    if (!buf) return NULL;
    snprintf(buf, 64, "SCORE: %d", score);
    return buf;
}
```

DS のゲームループの中では (a) が最も安全です。
</details>
