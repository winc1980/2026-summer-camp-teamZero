# TACTICS MVP

Nintendo DS向けの、2人対戦ターン制タクティクスゲーム。
1台の本体を交代で操作し、それぞれ3体のユニットを動かして相手チームの全滅を目指す。

## 制作背景

本作は、チーム内に『ポケモン＋ノブナガの野望』が好きなメンバーがいたことをきっかけに企画した。
同作を再現するのではなく、Nintendo DSiで動作し、短期間でも対戦ゲームとして完成させられる規模へアイデアを再構成している。

開発期間は、企画・実装・実機確認・発表準備を含めて実質約2.5日間。
限られた時間の中で遊べる状態まで到達することを重視し、まず移動・攻撃・ターン交代・勝敗判定からなる対戦の核を完成させ、その後に表示やサウンドを加える方針を採った。

## 設計方針

### 1台を囲んで遊ぶ

操作をプレイヤーごとに分けず、1台の本体を交代で操作する共通操作方式を採用した。
通信機能を前提とせずに対戦を成立させるためだけでなく、本体を受け渡しながら盤面について会話し、同じ場で遊ぶ体験を作ることも狙いとしている。

### DSiの画面に合わせた表現

小さな画面でもユニットや移動可能範囲を判別しやすく、短期間で全体の見た目を統一できるよう、シンプルなドット絵を中心に構成した。
上画面には盤面とユニットを、下画面には選択中ユニットの情報と操作内容を表示し、プレイ中に必要な情報を役割ごとに分けている。

### 判断材料を先に見せる

移動を確定する前に、カーソルを合わせた移動先からの攻撃可能範囲を表示する。
移動後に初めて攻撃可否が分かる状態を避け、プレイヤーが位置取りと攻撃を一続きの判断として考えられるようにした。

## チーム開発

6人チームで、企画、ゲームルール、画像、サウンド、画面表示などを分担して制作した。
企画段階で挙がった案はそのまま並行実装せず、次の情報を整理してIssueへ分割した。

- ゲームの完成に対する優先度
- 現在のコードを踏まえた実装難易度
- 各メンバーの自己申告による技術レベル
- 各作業への希望・非希望
- 他の機能との依存関係と競合の可能性

優先度を最初の判断基準としつつ、各メンバーが完了可能な難易度と、できる限り本人の希望に合う担当を組み合わせた。
最初は各メンバーが1件をPull Requestまで進めることを目標とし、完了後に次のIssueへ進む段階的な割り当てを行った。
作業が難航した場合は相談、レビュー、担当の引き継ぎによって全体の進行を優先した。

短期間ですべての案を実装することはせず、安定して対戦できる版を先に確保したうえで追加機能を統合した。
今回採用しなかった案も、検討した仕様、難易度、優先度をIssueに残し、今後の拡張候補として管理している。

## 特徴

- 上画面に8×6マスの盤面、下画面に操作と戦況を表示
- ユニットごとに異なる移動方法・攻撃範囲・攻撃力
- 移動先を確定する前に、その地点からの攻撃可能範囲を表示
- 攻撃できない状況をボタンの無効表示と操作制限の両方へ反映
- 日本語表示用の8×8ドットフォント描画
- 対戦中のBGM、選択時と勝敗決定時の効果音
- 勝敗決定後の結果表示とSTARTボタンによる再戦

## ゲームルール

Player 1から開始し、生存している自軍ユニットを1体ずつ行動させる。
1体の行動は「移動または現在地に残る」「攻撃または待機」の順に進む。
自軍の全員が行動すると相手のターンになり、相手の3体を先に倒した側が勝利する。

| ユニット | 攻撃力 | 移動・攻撃の特徴 |
|---|---:|---|
| A | 60 | 上下左右へ移動し、前方1〜2マスを攻撃 |
| B | 70 | 斜めと前方へ移動し、2マス前の横3マスを攻撃 |
| C | 40 | 前方・左右・後方へ移動し、斜め4方向を攻撃 |

全ユニットの初期HPは100。詳しい判定は[技術資料](mygame/docs/technical-notes.md)を参照。

## 操作

- 十字キー：盤面カーソルの移動、攻撃／待機の切り替え
- A：決定
- B：1段階戻る。移動後は移動前の位置へ戻る
- START：勝敗決定後に再戦

## ビルド

Docker、VS Code Dev Containersを用意し、Dev Container内で実行する。

```bash
cd /work/mygame
make clean
make
```

成功すると`mygame/mygame.nds`が生成される。melonDSまたは対応する実機環境で起動できる。

## ルールテスト

描画を除くゲームルールはPC上でも検証できる。

```bash
cd mygame
cc -std=c11 -Wall -Wextra -Werror -Isource \
  test/test_rules.c source/game.c source/board.c source/unit.c \
  -o /tmp/mygame-rule-tests
/tmp/mygame-rule-tests
```

`All game rule tests passed.`と表示されれば成功。

## 開発上の工夫

- ゲーム進行、盤面ルール、入力、描画、サウンドをファイル単位で分離
- DS固有処理に依存しないルール部分をホストPCでもテスト可能な構成にした
- ゲーム状態をフェーズで管理し、選択・移動・攻撃・ターン交代を明確化
- 状態に変化がないフレームでは下画面を描き直さず、表示のちらつきを抑制
- IssueとPull Requestを単位として機能を分担し、統合前にビルドと動作を確認
