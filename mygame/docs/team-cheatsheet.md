# 班員向け説明：チーム0のゲーム（仮）

## まず動かす

1. VS Code左下が `Dev Container: nds` になっていることを確認する。
2. ターミナルで `cd /work/mygame` を実行する。
3. `make` を実行する。
4. MacのFinderから `mygame/mygame.nds` をmelonDSで開く。

変更後に挙動がおかしいときは、`make clean` のあとに `make` を実行します。

melonDSのキー設定がAボタンだけの場合は、`Config → Input and Hotkeys → DS keypad` で次のように設定します。

- Up / Down / Left / Right：キーボードの矢印キー
- A：X
- B：Z
- Start：Enter（Return）

## 現在のゲームルール（必要なら変更）

- 盤面は横8マス、縦6マス。1マスは32×32ピクセル。
- Player 1は青、Player 2は赤。初期HPは全員100。
- 初期配置は、Player 2が上段、Player 1が下段。左からA・B・C。
- Player 1から開始し、1台のDSを交代で操作する。
- 1体の行動は「移動またはその場に残る → 攻撃または待機 → 終了」。
- 攻撃範囲はA・B・Cごとに異なり、範囲内から敵1体を選んで攻撃する。
- 防御力・属性相性はなく、Aは60、Bは70、Cは40ダメージ。
- 相手の3体を全滅させたら勝利。STARTで再戦できる。
- 生きている自軍全員が1回ずつ行動すると相手ターンになる。

### キャラクターの移動・攻撃範囲

- Aの移動：上下左右へ1マス。
- Aの攻撃：正面の1マス前または2マス前にいる敵1体。2マス前を攻撃するとき、間の1マスにキャラまたは通行不可地形があると届かない。
- Bの移動：斜め四方へ1マス、または正面へ1マス。横や縦の隣接マスが塞がっていても、斜めの着地点へ直接移動できる。
- Bの攻撃：2マス前の左・中央・右にいる敵1体。1マス前の3マスがキャラや地形で塞がっていても飛び越えて攻撃できる。
- Cの移動：左前・正面・右前の3マス、左右1マス、または真後ろ1マス。横や縦の隣接マスが塞がっていても、斜めの着地点へ直接移動できる。
- Cの攻撃：斜め四方の1マスにいる敵1体。横や縦のマスが塞がっていても斜めに攻撃できる。
- どの移動でも着地点は空いていて、通行可能である必要がある。
- 全員、その場に残って攻撃または待機を選べる。
- 「前」はPlayer 1では画面上、Player 2では画面下。

次の図はPlayer 1視点（上が前）。`○`が選択可能なマス、中央の文字が
現在のキャラクター位置。Player 2では上下を反転する。

```text
Aの移動       Aの攻撃
・○・         ・○・  2マス前
○A○         ・○・  1マス前
・○・         ・A・

Bの移動       Bの攻撃
○○○         ○○○  2マス前
・B・         ・・・  1マス前は飛び越える
○・○         ・B・

Cの移動       Cの攻撃
○○○         ○・○
○C○         ・C・
・○・         ○・○
```

Aの2マス攻撃だけは、1マス前がキャラまたは通行不可地形で塞がれていると
届かない。Bの2マス攻撃と、B・Cの斜め移動／Cの斜め攻撃は途中を調べない。

## 操作の流れ

```text
自分の未行動キャラを選ぶ
        ↓
水色で示された移動先を選ぶ
        ↓
攻撃 または 待機 を選ぶ
        ↓
攻撃なら赤色で示された攻撃範囲内の敵を選ぶ
        ↓
行動終了
```

移動後に攻撃範囲内の敵がいない場合は、`こうげき`が暗い灰色になって
選択できず、最初から`たいき`にカーソルが合う。Aを1回押せば行動終了する。

- 十字キー：カーソル移動、攻撃/待機切り替え
- A：決定
- B：戻る。移動先選択中はキャラ選択へ戻り、行動選択中は仮移動を取り消し、攻撃対象選択中は行動選択へ戻る
- START：勝敗決定後にリスタート

## ソースコードを読む順番

1. `source/main.c`：毎フレーム何をするかだけを見る。
2. `source/game_types.h`：ゲーム全体で使う型と定数を見る。
3. `source/input.c`：DSのキーをゲーム用の入力へ変換する。
4. `source/game.c`：選択、移動、攻撃、ターン交代、勝敗の流れ。
5. `source/board.c`：A・B・Cの移動条件と攻撃範囲。
6. `source/unit.c`：初期HPと攻撃力。
7. `source/render.c`：上画面の盤面・駒と下画面の文字配置。
8. `source/japanese_text.c`：日本語を含む8×8ドット文字の描画。

## ファイルごとの担当

| ファイル | 担当 | よく変更する例 |
|---|---|---|
| `game_types.h` | 定数、構造体、enum | 盤面サイズ、地形や行動の種類 |
| `unit.c` | キャラ固有値 | 攻撃力、初期化 |
| `board.c` | 盤面ルール | 移動範囲、地形の通行可否、攻撃範囲 |
| `game.c` | ゲーム進行 | ターン、選択順、ダメージ、勝敗 |
| `input.c` | キー割り当て | 左右分割操作 |
| `render.c` | 画面表示 | 色、画像、カーソル、HP表示 |
| `japanese_text.c` | 日本語フォント | 表示に必要な文字の追加 |
| `main.c` | メインループ | 基本的に触らない |

## READMEのC言語知識がどこに出てくるか

- 配列：`terrain[6][8]` が盤面、`units[6]` が全キャラ。
- 構造体：`Game` が盤面・キャラ・現在ターンをひとまとめに持つ。
- ポインタ：`Game *game` を関数に渡し、同じゲーム状態を更新する。
- enum：プレイヤー、キャラ、地形、操作段階に分かりやすい名前を付ける。
- switch：現在の操作段階やキャラ種類に応じて処理を分ける。
- ゲームループ：`main.c` の `while (1)` が入力・更新・描画を繰り返す。

## （重要！！）後から画像へ差し替える

現在の盤面とキャラは `render.c` がプログラム内で仮画像を作っています。画像素材が決まったら、ゲームルールには触れず `render.c` と `graphics/` を中心に変更します。

BlocksDSの一般的な流れは次の通り。

1. 32×32など、用途に合うサイズのPNGを用意する。
2. `graphics/` に入れる。
3. grit/Makefileの変換設定を追加する。
4. 生成された画像データを `render.c` から読み込む。
5. 透過色、色数、VRAM使用量を確認する。

（重要！）8×6盤面を全面画像48枚で持つ必要はありません。草1枚など同じタイルを繰り返し描画すれば容量を節約できます。現MVPのROMは約109KBで、まだ十分余裕があります。

素材サイトを使う場合は、利用規約、ゲームへの組み込み可否、改変可否、クレジット表記を確定前に確認してください。

## （重要！）日本語表示

DSの標準コンソールフォントには日本語がないため、下画面は16ビットのビットマップ画面へ直接文字を描いています。`japanese_text.c`には、8×8ドットの美咲フォントから現在の画面で使う文字だけを収録しています。

- 新しい日本語を表示したい場合、その文字のグリフを `japanese_text.c` へ追加する必要がある。
- 未収録文字は `?` として表示される。
- フォントの出典と利用条件は `docs/misaki-font-license.md` に記載している。

## 地形を追加する

地形用の型はすでに `TERRAIN_PLAIN`、`TERRAIN_MOUNTAIN`、`TERRAIN_RIVER`、`TERRAIN_BUILDING` を用意しています。

1. `boardInit()` で各マスの地形を設定する。
2. `boardTerrainIsWalkable()` で通行ルールを決める。
3. `terrainColor()` または後日の画像対応で見た目を設定する。
4. `test/test_rules.c` に移動可否テストを足す。

B・Cの斜め移動では横・縦の隣接地形を無視しますが、着地点そのものが
通行不可なら移動できません。Bの2マス攻撃は1マス前の地形を飛び越え、
Aの2マス攻撃は1マス前の地形で遮られます。これらの判定は`board.c`に
まとまっています。

## 左右分割操作を追加する

ルール側は `GameInput` だけを受け取るため、主に `input.c` を変更します。

- Player 1：十字キー、L決定、SELECTキャンセル
- Player 2：ABXY、R決定、STARTキャンセル

`game.c`へ直接DSのキー名を書かないことが重要です。そうすれば操作変更がゲームルールへ波及しません。

## （重要！！）今は入っていないもの

- 草・山・川・建造物の最終画像と配置
- A・B・Cの最終キャラクター画像
- アイテム（`ACTION_ITEM` という予約だけあり、選択肢には未表示）
- 左右分割操作
- 効果音・BGM
- タイトル画面
- 演出やアニメーション

## （重要！！）壊しにくくするルール

- 移動ルールは `board.c`、ゲーム進行は `game.c`、見た目は `render.c` に置く。
- `main.c`へ個別ルールを足さない。
- 座標は左上が `(0, 0)`。xは右へ、yは下へ増える。
- 配列へアクセスする前に `boardIsInside()` で盤面内か確認する。
- 倒れたキャラは `alive == false` とし、盤面判定から除外する。
- 仕様変更時は `test/test_rules.c` も一緒に変更する。

## 困ったとき

- `Nothing to be done for 'all'.`：エラーではなく、変更がないという意味。
- ヘッダに赤線が出る：Dev Containerで開けているか確認する。
- `.nds`が更新されない：`make clean` → `make`。
- 画面が古い：melonDSでROMを開き直すかリセットする。
- ビルドエラー：最初に表示された `error:` の行とファイル名を見る。後ろのエラーは連鎖のことが多い。
